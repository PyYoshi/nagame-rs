# Nagame（ながめ）

画像を眺め、フォルダをめくるための、Rust / GPUI 製画像ビューアーです。Linux向けに開発しています。日本語と英語に対応し、初回はOSの言語に合わせます（日本語以外は英語）。設定で選んだ言語は保存して次回も使います。

エージェント向けの入口は [AGENTS.md](AGENTS.md) です。文書全体は [ドキュメント案内](docs/README.md) を参照してください。

## 起動

```sh
cargo run --release -- /path/to/image.png
cargo run --release -- /path/to/images
```

引数なしでも起動できます。「開く」、Ctrl+O、ファイル／フォルダのドロップで画像またはPDFを選択します。同じフォルダ内の対応画像を数値順（1、2、10）に並べ、先頭・末尾では移動先を選択できます。PDFは開くとそのページを文書順に並べ、画像と同じ操作でページを送ります。

ビルド済みバイナリは `./target/debug/nagame` です。開発ビルドも画像処理を最適化する設定に変更しました。

## 実装した機能

- PNG / JPEG（jpg/jpeg/jpe）/ BMP / GIF（アニメーション）/ WebP / TIFF / ICO / AVIF / HEIF / HEIC / PDF
- PDFのページ送り・見開き・回転・保存。スキャンした本は埋め込み画像の解像度で、文字や図形のページは拡大に合わせて描き直して表示（PDFiumを別プロセスで実行）
- 巻ごとのPDFを、フォルダ移動・最終ページからの移動で続けて表示
- 非同期デコード、EXIF Orientation、古い読み込み結果の破棄
- フォルダ内の画像送り、先頭／末尾へ移動
- 子孫を含む前後のフォルダ移動（空フォルダを飛ばす）、同階層の隣接移動（空も含む）、親フォルダ移動
- メモリー予算に連動するデコード済みキャッシュ（最大8画像）と前後画像の先読み
- GIFの逐次デコード（先頭フレームから再生開始、大きなGIFは再生済みフレームを捨てて繰り返し読み直す）
- フィット（小さい画像は拡大しない）、原寸、ズーム、ドラッグによるパン
- 拡大・縮小別の表示補間選択（GPU Linear / 最近傍 / バイリニア / バイキュービック / Lanczos3）
- 90度右回転、全画面、間隔を変更できるスライドショー
- メニューバー、右クリックメニュー、画像情報、クリップボードへの画像／パスコピー
- マンガの見開き、右／左開き、横長ページの単独表示
- 並び順・数値順・逆順、フォルダ境界・ズーム等の設定と永続化、キー割り当て変更
- 表示画像のPNG/JPEG/GIF/BMP/WebP/TIFF/ICOへの書き出し
- 画像サイズ・倍率・ファイル名の表示、読み込み失敗の表示

回転は表示に適用します。「名前を付けて保存」で回転・見開きの結果を書き出せます。

### メモリーの使い方

画像データに使うメモリーは予算で管理します。予算は設定の「画像に使うメモリーの上限」で選び、既定の「自動」ではRAM（cgroupの制限があればその値）の1/8を256 MiB〜2 GiBに収めた値です。空き容量が少ない場合（使用中の量＋空き容量の半分までに抑えます）やメモリー逼迫を検知した場合は自動で下げ、OSの情報で予算を上げることはありません。予算は展開データの目安であり、アプリ全体のピークメモリー上限ではありません。

| 用途 | 上限 |
|---|---|
| 1枚の画像・GIFの1フレーム・見開き合成 | 予算（128 MiB〜1 GiB）。1辺は16,384ピクセルまで |
| 全フレームを保持して再生するGIF | 予算の1/2（128 MiB〜1 GiB） |
| 逐次デコード時の先読み | 予算の1/8（32〜256 MiB）。再生0.5〜2秒分を目標に、追いつかなければ増やす |
| 表示補間の出力・PDFの描き直し | 予算の1/4（128〜512 MiB） |
| デコード済みキャッシュ | 予算から表示中の画像を除いた残り |

PDFのページは、描いた画像を他の画像と同じ予算で扱います（1ページは上記の1枚の上限まで）。PDFを読み込む別プロセス（PDFium）のメモリーは予算の外で、RAMの1/4（1〜4 GiB）を上限とし、メモリー逼迫時は開いている文書を閉じ、続けて逼迫するとプロセスを止めます（次のページで起動し直します）。

GIFのフレーム数に上限はありません。全フレームが保持の上限に収まるGIFは一度デコードして繰り返し再生し、超えるGIFは再生済みのフレームを捨ててループごとにファイルから読み直します。切り替えのために先頭から読み直すことはありません。

メモリー逼迫を検知すると、1回目でキャッシュを表示中の画像だけにして先読みを止め、デコード中のGIFは全フレーム保持の試みをやめて先読みを最小にします。続けて検知すると表示補間の結果を捨て、全フレームを保持中のGIF（先読みの上限より大きいもの）も先頭フレームと再生中の数フレームだけを残して逐次デコードへ移します。最後の検知から30秒で予算・補間・先読みを戻しますが、逐次デコードへ移ったGIFは開き直すまでそのままです。検知にはPSI（Linuxのメモリー停止の通知）と空き容量を使います。PSIの通知は他のプロセスのスワップ読み戻しなどでも届くため、空き容量がRAMの10%（最低512 MiB）未満の場合に限ります。通知がなくても5%（最低256 MiB）未満なら逼迫とみなします。cgroupの使用量からは回収可能なページキャッシュを除きます。解放した画素バッファはOSへ返します。

## ビルド環境

Rust 1.99.1、GPUI 0.2.2 でビルド・テストしています。依存は `Cargo.lock` に固定しています。LinuxではVulkan対応環境、WaylandまたはX11、Fontconfig、FreeType、xkbcommon関連とlibheifの開発ライブラリが必要です。AVIF用AV1デコーダーとHEIC用HEVCデコーダーも必要です。

Fedora/Nobara系の開発用パッケージ例：

```sh
sudo dnf install libheif-devel libxkbcommon-x11-devel
```

通常のビルドコマンドは以下です。

```sh
cargo build --locked
```

PDFの表示には [PDFium](https://pdfium.googlesource.com/pdfium/) の共有ライブラリが必要です。システムのパッケージではなく、固定版のビルド（[bblanchon/pdfium-binaries](https://github.com/bblanchon/pdfium-binaries)）を `just pdfium` で取得し、SHA256を照合して `target/pdfium/` に置きます。`cargo run` と `cargo test` はこのライブラリを使います。AppImageには同梱します。PDFiumが見つからない場合も画像は表示でき、PDFを開くとエラーを表示します。フォントが埋め込まれていない日本語のPDFには、Noto CJK等の日本語フォントがホストに必要です。

Linuxで画像をクリップボードへ渡す処理は、Waylandセッションでは `wl-copy`（wl-clipboard）、X11セッションでは `xclip` を使用します。GPUI 0.2.2の標準Linuxコピー経路は外部アプリへ画像形式を公開しないため、この処理を補っています。

GPUIの間接依存 `xattr 0.2.3` は新しいlibcと互換性がなかったため、`vendor/xattr` にLinux/Androidの `ENOATTR` を `ENODATA` に置き換えるパッチを含めています。元のMIT/Apacheライセンスを同梱しています。

```sh
cargo fmt --all --check
cargo test --locked
cargo clippy --locked --all-targets --all-features -- -D warnings
```

## 現時点の範囲

PDFはページを画像として眺める機能に限ります。テキストの選択・検索、リンク、フォーム入力、注釈の編集、しおり、パスワードで保護されたPDF、印刷、PDF形式での保存には対応しません。見開きで文字のページを拡大したときは描き直さず、拡大表示します。埋め込まれていない日本語フォントはホストのフォントで代替し、明朝の指定もゴシック体で表示されることがあります。

書庫、削除・移動・名前変更、回転以外の画像編集、編集履歴、ICCカラーマネジメントは未実装です。書き出しは元のEXIF・ICC等を保持せず、AVIF/HEIC形式での保存はできません。アニメーションはGIFに対応し、WebP/APNG等のアニメーション、複数ページTIFFは初期画像のみです。GIFのループ回数指定には対応せず繰り返し再生します。10ms以下の遅延は主要ブラウザと同じく100msとして再生します（保存時は元の値）。

自動テスト64件はソート、ナビゲーション、表示計算、PDF（合成PDFの寸法・色・分類と解像度・エラー・補助プロセスの再起動と時間制限・ページ列と探索・見開き）、色順／回転、GIFの逐次デコード・全フレーム保持・先読み・保存、メモリー予算・台帳・逼迫判定、AVIF/HEICの実コーデック、設定保存、ウィンドウ状態の保存・復元、見開き（幅0の画像の拒否を含む）、画像保存を対象にしています。実ウィンドウで設定の保存・再起動・キー変更・見開きと1,400回の画像送り、GIFの再生・補間・逐次デコード・GIFとPNGを混ぜた480回の画像送り・逼迫時の削減、PDFの描き直し・200回のページ送り・見開き・逼迫後の回復・次のPDFへの移動も確認しました。[開発・検証の手動回帰確認](docs/development.md#手動回帰確認)に沿って実機で確認してください。

## 読み込みとフォーマット

読み込み・キャッシュ・フォルダ移動の実装は [コード構成と設計](docs/architecture.md) を参照してください。

HEIF系はコンテナの回転・反転と8/10bit入力をlibheifで処理し、8bit RGBAへ変換して表示します。HDRトーンマッピング・ICCによる完全な色管理・アニメAVIFには未対応です。

`NAGAME_PROFILE=1 ./target/debug/nagame IMAGE` で読み込み時間、キャッシュヒット、画像データの保持量・予算・GIFの保持方式、メモリー逼迫への対応を標準エラーへ出力します。`cargo run --bin decode-bench -- IMAGE...` でGUIを含まないデコード時間を測れます。

連続画像送り時のクラッシュを防ぐ画像解放の条件は [テクスチャの退役](docs/architecture.md#テクスチャの退役)、回帰テストは [開発・検証](docs/development.md) を参照してください。

## 設定と表示

Ctrl+,で設定（Settings）を開きます。移動・並び順、表示・漫画、読み込み・スライド、キー設定の4タブがあり、変更は保存するまで適用されません。Enterで保存、Escでキャンセルします。「初期値に戻す」（Restore defaults）も保存前は下書きです。設定の複数候補がある項目は「▾」から一覧を開きます。キーボードではSpaceで一覧、↑↓で候補、Enterで決定、Escで一覧だけを閉じます。

キー設定は項目を選びSpace、続いて割り当てるキーを押します。同じ機能の既存キーは置換され、別の機能で使用中のキーは新しい機能へ移ります。Deleteで割り当て解除、Escでキー入力を中止します。

真偽値の設定はチェックボックスで表示します。チェックありは有効、なしは無効です。チェックボックスまたは項目名のクリック、キーボードでは項目を選んでSpaceで切り替えます。変更は保存するまで下書きで、Escでキャンセルできます。

読み込み・スライド（Loading & slideshow）の「画像に使うメモリーの上限」（Image memory limit）で、自動・256 MiB〜8 GiBを選べます。設定ファイルでは `memory_limit_mib`（0は自動、128以上）です。

表示・漫画（Display & manga）の表示言語（Language）で、システムに合わせる・日本語・Englishを選べます。言語未指定の既存設定もOSに合わせて表示し、手動で保存した指定を優先します。

設定は `$XDG_CONFIG_HOME/nagame/settings.json`、未設定時は `~/.config/nagame/settings.json` に保存します。壊れた設定ではエラーを表示して既定値で起動し、明示的な保存まで元ファイルを保持します。メニューの並び順変更とMによる見開き切替も保存します。

ウィンドウの通常サイズと最大化状態は終了時に自動保存し、次回起動時に復元します。X11では位置も復元します。Waylandの位置はコンポジターに任せます。全画面表示は復元せず、全画面化・最大化する前の通常サイズを保持します。状態は設定ファイルと同じディレクトリの `window-state.json` に保存します。壊れた状態ファイルでは既定値を使い、画面情報を取得できる場合は画面外の位置や大きすぎるサイズを補正します。

「前の画像」で先頭を越えて前のフォルダへ移動するときは、そのフォルダの最後の画像を開きます。「次の画像」で末尾を越えるときは、次のフォルダの先頭画像を開きます。境界での確認ダイアログからフォルダへ移動する場合も同じです。「『前のフォルダ』で先頭画像を開く」設定は、前のフォルダ・前の同階層フォルダへの直接移動に適用し、画像送りによるフォルダ移動には適用しません。先頭・最後は現在の並び順に従います。

見開きは右から左の場合、現在の画像を右、次を左へ配置します。横長画像の単独表示を設定でき、前進は表示したページ数だけ進みます。結合画像がサイズ上限を超える場合は1ページ表示へ戻ります。見開きは静止画として合成するため、GIFも先頭フレームのみです。

表示補間は拡大・縮小別にGPU Linear（既定）、最近傍、バイリニア、バイキュービック、Lanczos3から選びます。GPU以外は非同期で処理し、連続ズームは60ms待ってから処理します。結果待ちや、出力が1辺16,384ピクセル・補間の上限（全フレーム合計）を超える場合はGPU表示を使います。GIFは全フレームのデコード後に補間し、逐次デコード中はGPU表示です。補間の変更は保存・コピーの解像度には影響しません。

保存は回転・見開きを反映した元解像度の画像を使います。単独表示のGIF保存はフレームと時間を引き継ぎ、他形式への出力は先頭フレームです。逐次デコード中のGIFは元ファイルから順に読み直して書き出します。
